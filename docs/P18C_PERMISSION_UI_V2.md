# P18C 用户权限页信息架构重构(参考 enprizon-stock 用户组管理)

> 2026-08-14 制定。用户反馈当前"用户权限管理+角色权限编辑"两板块同屏堆叠逻辑混乱,参考 enprizon-stock 的用户组管理信息架构重构。用户确认:两个平级 Tab + 单选角色。

## 一、当前问题

同屏堆两个不同心智模型(用户为中心 vs 角色为中心),无关联导航;"角色默认权限"与"单用户覆盖"叠加关系不可见;行内"展开权限"把每个用户的完整权限暴露为编辑入口,概念不干净。

## 二、stock 可借鉴模式

1. 用户/组(角色)是两个**独立实体**,各有编辑入口(平级区块)
2. 抽屉式编辑(点行 → 右抽屉),不跳页、不堆叠
3. 组=权限单元,组详情内嵌权限矩阵(本地暂存+显式保存+Reset)
4. 用户详情内分配组 + 改密码 + 锁定

## 三、已确认决策

| # | 决策 | 结论 |
|---|------|------|
| 1 | UI 结构 | **两个平级 Tab**:用户管理 / 角色管理 |
| 2 | 多角色 | **单选角色**(保留现状 admin_users.role) |
| 3 | 数据模型 | 保留 role_permissions + user_grants,不迁移 |

## 四、新页面设计

### 系统 → 用户权限 = 两个平级 Tab

```
┌─ 系统 → 用户权限 ─────────────────────────────────────┐
│ [👥 用户管理]  [🎭 角色管理]       ← 平级 Tab,当前高亮 │
│                                                    │
│ ══ Tab「用户管理」:账号维度 ══                       │
│  顶部说明: 管理登录账号,分配角色。角色权限请在"角色管理"设置 │
│  用户列表: 用户名 | 角色 | 状态 | 操作                │
│    user   查看者  正常  [编辑]                       │
│    KEJU   管理员  正常  [编辑]                       │
│   [＋ 新增用户]                                     │
│   点「编辑」→ 右抽屉(用户编辑抽屉):                    │
│     ① 账号信息: 用户名 / 状态(启用/锁定)              │
│     ② 分配角色: 下拉单选(查看者/编辑员/管理员)         │
│     ③ 单用户权限覆盖(可选): allow/deny 列表           │
│        · 显示该用户相对角色的覆盖项                    │
│        · 每行: 权限名 + 允许/拒绝 + 删除              │
│     ④ 改密码 / 删除账号                              │
│                                                    │
│ ══ Tab「角色管理」:角色维度 ══                       │
│  顶部说明: 定义各角色的默认权限,保存后该角色用户重新登录生效 │
│  角色列表: 查看者 | 编辑员 | 管理员(卡片或行)          │
│   [＋ 新建角色](可选,本期不做则隐藏)                   │
│   点角色 → 右抽屉(角色编辑抽屉):                       │
│     ① 权限矩阵: 8 功能域 × 17 权限项勾选(checkbox+功能名+说明) │
│     ② 继承提示: 编辑员继承查看者(灰标签"来自查看者" disabled) │
│     ③ 底部操作: 未保存 N 项 | 保存 / 撤销 / 恢复默认    │
└────────────────────────────────────────────────────┘
```

### 交互要点

- **Tab 切换**:用户管理/角色管理平级切换,当前高亮;切换不影响未保存草稿(各自独立 dirty 状态)
- **抽屉**:点行"编辑"打开右抽屉(overlay + 侧滑面板),关闭不丢失(或提示未保存)
- **用户编辑抽屉**:
  - 角色下拉:单选,改角色保存后该用户需重新登录生效(提示)
  - 单用户覆盖:加载该用户 user_grants(allow/deny 列表),可新增(选权限+允许/拒绝)/删除;显示当前生效权限来源(角色默认 vs 单用户覆盖)
  - 改密码/删除:复用现有 API
- **角色编辑抽屉**:复用 P18b 的权限矩阵逻辑(功能分组/继承/未保存计数/保存/撤销/恢复默认),只是搬进抽屉
- **说明文案**:两 Tab 顶部各有 1 行说明,明确"账号维度"vs"角色维度"

## 五、后端配合(少量)

- `GET /api/permissions/users` 现有返回用户+permissions 摘要,需补充每个用户的 role + 单用户 grants 明细(供用户抽屉)
- `POST /api/permissions/grant`(allow)现有;**新增 deny 支持**:`POST /api/permissions/grant` body 支持 grant_type=deny(或新增端点)。用于用户抽屉"单用户覆盖-拒绝"
- 角色权限 API(GET/PUT /api/permissions/roles)已支持,复用
- 用户改角色/改密/删除:现有 /admin/users 系列 API,复用

## 六、实施范围(前端为主)

- `templates/index.html` 权限管理页(loadPermissionsPage 附近,6768-6933 区域)重构:
  - 改为两个平级 Tab 容器
  - 用户管理 Tab:用户列表(复用现有表格样式)+ 用户编辑抽屉(新组件)
  - 角色管理 Tab:角色列表(卡片/行)+ 角色编辑抽屉(从现有 rolePermCard 迁移)
  - 抽屉组件:overlay + 侧滑面板 CSS
- `static/js/i18n.js`:新增 Tab/抽屉/文案键(zh/en)
- 移动端不受影响(权限管理仅桌面端)

## 七、验收标准

1. 用户权限页显示两个平级 Tab(用户管理/角色管理),切换正常
2. 用户管理:列表显示用户名/角色/状态;点编辑开抽屉:改角色保存生效(该用户重登)、单用户覆盖可加 allow/deny、改密码、删除
3. 角色管理:角色列表;点角色开抽屉:权限矩阵勾选/继承标签/未保存计数/保存/撤销/恢复默认
4. 抽屉关闭不丢失未保存(或明确提示)
5. viewer/admin 权限过滤仍生效(页面级、按钮级)
