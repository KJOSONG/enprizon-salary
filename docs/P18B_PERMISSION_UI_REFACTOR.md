# P18b 权限管理 UI 重构设计

> 2026-08-14 制定。用户反馈角色权限编辑 UI 不清晰(不知在改谁、勾选无反馈、产量权限不知在哪),确认 3 项决策后重构。
> 前置:P18 权限框架(role_permissions 表 + check_permission + 角色继承)已完成。

## 一、用户反馈的问题

1. 不知道是否在真的编辑某人的权限(三角色混一张 120 格大表,无"当前角色"概念)
2. UI 勾选没有及时显示(勾选后仅底部小字"有未保存的修改")
3. 整个板块不清晰明了(8模块×5动作=40行,大量无效组合如 dashboard:approve)
4. 产量权限涉及哪里不清楚(权限项与系统功能无对应说明)

## 二、已确认决策

| # | 决策 | 结论 |
|---|------|------|
| 1 | 视图模式 | **角色中心 + 功能分组**(Tab 切换角色,按功能域分组显示权限项) |
| 2 | 权限项收敛 | **收敛为真实有效项**(前后端实际挂载/使用的权限项) |
| 3 | 功能说明 | **每项权限带中文功能说明**(直接回答"产量权限=采集提交") |

## 四、UI 设计

### 4.1 布局(角色中心 + 功能分组)

```
┌─ 权限管理 ─────────────────────────────────────────────┐
│ [用户管理 Tab][角色权限 Tab]                              │
├────────────────────────────────────────────────────────┤
│ 正在编辑角色:  [管理员] [编辑] [查看者]   (Tab,当前高亮)   │
│ 说明: 勾选允许,取消禁止。保存后该角色用户重新登录生效。     │
│ 继承提示: editor 自动继承 viewer 权限(灰标签"来自查看者")  │
├────────────────────────────────────────────────────────┤
│ ▸ 数据台                                                 │
│   [✓] 数据台  — 查看数据台产量看板                       │
│ ▸ 产量                                                   │
│   [✓] 产量查看  — 查看井下/钻工/破碎产量数据              │
│   [✓] 产量采集  — 提交井下/钻工/破碎/出勤收集数据         │
│ ▸ 出勤                                                 │
│   [✓] 出勤查看  — 查看出勤网格                           │
│   [✓] 出勤编辑  — 标记/批量修改出勤,保存计算              │
│   [✓] 出勤导出  — 导出出勤 Excel                         │
│ ▸ 员工 ...                                              │
│ ▸ OA ...                                                │
│ ▸ 薪资 ...                                              │
│ ▸ 评分 ...                                              │
│ ▸ 系统 ...                                              │
├────────────────────────────────────────────────────────┤
│ 未保存修改: 2 项    [保存] [撤销修改] [恢复默认]          │
└────────────────────────────────────────────────────────┘
```

### 4.2 交互细节

- **角色 Tab**:点击切换,加载该角色全部权限(从 /api/permissions/roles 按 role 过滤);当前角色高亮
- **权限项开关**:checkbox/switch,勾选即该项行高亮(未保存态背景),右上角"未保存修改 N 项"实时更新
- **继承显示**:被继承的下级权限项(如 editor 的 dashboard:view 来自 viewer)显示灰标签"来自查看者",可点击查看来源,不重复设置(disabled 或提示)
- **操作条**:底部固定,[保存]PUT 该角色全部变化;[撤销修改]重置 dirty;[恢复默认]调后端重置该角色为 ROLE_DEFAULT_PERMISSIONS 默认值
- **功能说明**:权限项名称右侧灰字说明(直接可读);点击名称弹 toast 或详情(可选)
- **保存反馈**:成功 toast"已保存,该角色用户重新登录生效"+ 刷新;失败红字
- **super_admin**:不显示在角色 Tab(不可编辑),顶部说明"超级管理员拥有全部权限,不可修改"

### 4.3 后端配合

1. `/api/permissions/roles` GET 返回结构支持按角色取权限(现有返回全表,前端过滤即可;或加 ?role= 参数)
2. **新增恢复默认**:`POST /api/permissions/roles/reset` body `{role}` → 将该角色 role_permissions 重置为 ROLE_DEFAULT_PERMISSIONS 默认(admin/editor/viewer)
3. **补齐查看类端点 enforcement**(使"取消查看权限"真实生效):
   - `GET /attendance` → `('attendance','view')`
   - `GET /employees`、`/api/employees` → `('employees','view')`
   - `GET /production`、`/api/production/dashboard` → `('production','view')`
   - `GET /api/scoring/*` → `('scoring','view')`
   - `GET /api/oa/pending`、`/api/oa/history` → `('oa','view')`
   - `GET /api/collection/history` → `('production','view')`(采集历史属于产量)
   - 注意:这些端点当前 `@login_required` 或角色装饰器,叠加 `@require_permission` 后 viewer 默认(仅 dashboard:view)将不能看产量/出勤/员工等——**需确认是否符合业务预期**(viewer 应能看到哪些?)

## 五、待确认(实施前)

1. **viewer 可见范围**:重构后 viewer 默认只有 dashboard:view,产量/出勤/员工等查看全关。当前 viewer 能看这些。是否收紧?(建议:viewer 默认可看 数据台+产量+出勤+员工(只读),不可编辑/导出/薪资/评分)——即查看类默认开放给 viewer,编辑/导出/薪资/系统默认关闭,管理员可再调整
2. scoring 模块当前用角色装饰器(editor),迁移到 scoring:view/edit 后口径变化
3. 权限项中"无效但角色级控制"的功能(如员工查看当前无细粒度权限,挂后口径变化)

> 建议:实施前先与用户确认 viewer 默认可见范围,避免上线后 viewer 大量功能受限。
