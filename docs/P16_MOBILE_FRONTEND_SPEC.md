# P16：移动端专属前端方案

> **日期**: 2026-08-13
> **范围**: 移动端专属前端（`templates/mobile.html`），覆盖数据台、员工、出勤、数据采集四大核心板块
> **原则**: 零后端改动，API 完全复用，i18n 翻译字典共享，Golden Time 设计 token 继承

---

## 1. 架构决策

### 1.1 为什么是独立模板，而非响应式改造

| 因素 | 当前响应式 | 独立移动端 |
|------|-----------|-----------|
| 代码膨胀 | 6983 行单文件继续膨胀 | 移动端独立文件，桌面端不变 |
| 信息架构 | 21 页侧边栏 → 移动端隐藏 | 4 模块底部 Tab Bar 直达 |
| 表格密集型页面 | `overflow-x:auto` 勉强可用 | 卡片化逐行展示，原生移动控件 |
| 回归风险 | 改动桌面端 CSS 可能波及所有页面 | 零风险，桌面端完全不动 |
| 维护心智 | 上下文切换成本高 | 独立心智模型，边界清晰 |
| 文件体积 | 6983 行全量加载 | 移动端按需加载，首屏更小 |

**结论**: 在 `templates/mobile.html` 中新建独立 SPA，共享后端 API 和 `i18n.js`。

### 1.2 路由策略

```
Flask 路由:
  GET /m          → mobile.html (移动端)
  GET /           → index.html  (桌面端，不变)

User-Agent 检测:
  - 移动端浏览器首次访问 / → 302 重定向到 /m
  - 桌面端浏览器访问 /m → 正常渲染（不做反向重定向，允许调试）
```

```python
# app.py 新增路由
@app.route('/m')
def mobile_index():
    return render_template('mobile.html')

# UA 检测中间件（仅对 / 路径生效）
@app.before_request
def mobile_redirect():
    if request.path == '/' and is_mobile_device():
        return redirect('/m')
```

## 2. 全局导航架构

### 2.1 底部 Tab Bar（4 项）

```
┌──────────────────────────────────────────┐
│  Period Bar (月份 + 搜索)                  │  ← 固定顶栏 48px
├──────────────────────────────────────────┤
│                                          │
│  当前 Tab 页面内容                         │  ← 可滚动主区域
│                                          │
│                                          │
├──────────────────────────────────────────┤
│  📊 数据台  │  👥 员工  │  📋 采集  │  ⏱ 出勤  │  ← 底部 Tab Bar 56px
└──────────────────────────────────────────┘
```

**设计约束**:
- 高度 56px，带 `safe-area-inset-bottom` 适配
- 4 项等宽分布，当前 Tab 高亮为 `--primary` 色
- 图标使用 SVG inline（不依赖外部图标库），统一 24x24
- 切换 Tab 不重新请求 API（首次加载后缓存 `STATE`）
- 底部 Tab Bar 固定，页面内容区 `padding-bottom: calc(56px + env(safe-area-inset-bottom))`

### 2.2 顶栏 Period Bar

```
┌──────────────────────────────────────────┐
│  [<] 2026年8月                    [🔍] [🌙] │
└──────────────────────────────────────────┘
```

- 左侧: 返回按钮（Tab 内子页回退时显示）+ 当前月份
- 右侧: 搜索图标 + 主题切换图标
- 点击月份: 弹出月份选择器（底部 Sheet）
- 点击搜索: 顶部展开搜索输入框，防抖 300ms
- 高度 48px，带 `safe-area-inset-top` 适配

### 2.3 页面栈导航

移动端采用"页面栈"模式替代侧边栏子页展开：

```
Tab 首页 → 点击某行 → 详情页（push）
         → 返回按钮 → 详情页（pop）
```

- 每个 Tab 维护自己的页面栈
- 顶栏"<"返回按钮在栈深度 > 1 时显示
- 切换 Tab 时保留各 Tab 的栈状态

```javascript
const STATE = {
  // 认证

  // 评分数据
  scoring: null,        // 评分汇总

  activeTab: 'dashboard',
  tabStacks: {          // 每个 Tab 的页面栈
    dashboard: ['dashboard'],

  },

```

### 10.2 API 调用策略

| 场景 | 策略 |
|------|------|
| 首次加载 | 并行请求 auth + employees + attendance + dashboard |
| Tab 切换 | 从 STATE 缓存读取，不重新请求（除非超过 5 分钟） |
| 下拉刷新 | 重新请求当前 Tab 相关数据 |
| 数据提交 | 提交后局部更新 STATE，不重新请求全部数据 |
| 月份切换 | 重新请求全部数据 |
| 搜索/过滤 | 前端 STATE 过滤，不请求 API |

### 10.3 页面栈管理

```javascript
// push 页面
function pushPage(tabName, pageName, params = {}) {
  STATE.tabStacks[tabName].push({ name: pageName, params });
  renderTab(tabName);
}

// pop 页面
function popPage(tabName) {
  if (STATE.tabStacks[tabName].length > 1) {
    STATE.tabStacks[tabName].pop();
    renderTab(tabName);
  }
}

// 切换 Tab
function switchTab(tabName) {
  STATE.activeTab = tabName;
  document.querySelectorAll('.tab-page').forEach(p => p.classList.remove('active'));
  document.getElementById(`tab-${tabName}`).classList.add('active');
  updateTabBar(tabName);
  updateTopBar(tabName);
}
```

## 12. 与桌面端的关系

```
                  ┌─────────────┐
                  │  Flask API  │  ← 43 个端点，零改动
                  └──────┬──────┘
           ┌─────────────┼─────────────┐
           ▼             ▼             ▼
    ┌──────────┐  ┌──────────┐  ┌──────────┐
    │ i18n.js  │  │  STATE   │  │  Auth    │  ← 共享层
    └────┬─────┘  └────┬─────┘  └────┬─────┘
    ┌────┴─────┐  ┌────┴─────┐
    │ index.html│  │mobile.html│  ← 两个独立 SPA
    │ style.css │  │mobile.css │
    └──────────┘  └──────────┘
```

**关键原则**:
- 后端 API 零改动
- i18n 字典共享，仅新增移动端专属键
- 认证 cookie 共享，无需重新登录
- 两个前端完全独立迭代，互不影响
- 桌面端现有功能不受任何影响

## 13. 风险与缓解

| 风险 | 概率 | 缓解措施 |
|------|------|----------|
| 移动端 JS 代码量超预期 | 中 | 按模块拆分内联 `<script>` 标签，Phase 1 先验证骨架复杂度 |
| Chart.js 在移动端性能问题 | 低 | 延迟加载 + 减少动画 + 降低数据点密度 |
| 双模板同步维护成本 | 中 | 共享 STATE 结构 + API 调用模式，仅 UI 层分叉 |
| iOS Safari 兼容性问题 | 中 | Phase 5 真机测试，`-webkit-` 前缀，safe-area 适配 |
| 出勤网格横向滑动体验 | 中 | 使用 `scroll-snap-type` 提升滑动体验，必要时降级为日期选择器 |
| 用户习惯桌面端功能 | 低 | 移动端聚焦高频场景，低频功能引导桌面端 |
