# 计件薪资制度 V2 — 逻辑规格说明（AI 可读）

> **文档目的**：描述"闸控计件（凸性加速）"这一**变更逻辑**，作为后续薪资系统代码改造的对照规格。本文**不含任何代码**，只描述规则、公式、参数与开关，供 AI / 开发者阅读理解。
>
> **适用范围**：井下出渣及采矿班组（每班 7 人，目标 40 车次/日）。
>
> **文档状态**：所有参数已与管理者确认；本次新增"凸性开关"概念（见 §0）。
>
> **重要定位**：本变更是**在现有计件（piecework）模式上的增量扩展**，由一个布尔开关控制，**不是新增第三种计薪模式**。

---

## 0. 模式定位与开关（必读）

系统当前已有两种计薪模式：

| 模式 | 性质 |
|---|---|
| `scoring` | 评分制：固定月薪 + 奖金池 |
| `piecework` | 线性计件：按「物料 × 单价」日池、按人头均分 |

本次 V2 = **`piecework` 模式的扩展**，由一个布尔开关 `piecework_accelerator` 控制：

| 开关状态 | 日池倍率 | 月末再分配 | 等价形态 |
|---|---|---|---|
| **关闭（OFF）** | 恒为 `1.0` | 否 | = 现有**普通线性计件**（与系统既有 `piecework` 完全等价，可随时回退） |
| **开启（ON）** | `total/40`（豁免日锁 `1.0`） | 是（出勤 + 行为系数，零和归一） | = **凸性加速计件**（V2 全量） |

**关键含义**：
- 关闭开关 → 退回普通线性计件，任何现场、任何时期都安全。
- 开启开关 → 启用凸性加速 + 月末出勤/行为再分配，彻底拉开差距。
- 凸性来源：日池金额已随车数线性增长，再乘「车次比」，工资对产量的弹性 ≈ 2（双倍敏感）。开关关闭时该倍率恒为 `1.0`，整个公式退化为线性。

---

## 1. 设计目标与原则（仅在开关 ON 时全部生效）

| 目标 | 说明 |
|---|---|
| 治懒（核心） | 工资 = 产量的**凸函数**：多干多得、少干少得，强制拉开差距，消灭"干多干少一个样"。（开关 OFF 时为线性，无此强制拉距效果） |
| 引导正确产出 | 物料差异化定价：MAWE 降价（压废石）、NICKEL H 提价（拉高品位矿），把激励从"多装"扭向"装值钱的"。 |
| 短反馈闭环 | 每日独立核算、每周公示看板、月末结算。 |
| 总额硬约束 | 月末实发总额 = 全月班组池之和（零和再分配，不多发、不少发）。仅开关 ON 时月末再分配生效。 |
| 可追溯 | 所有分配以"每日实际花名册 + 物料车次记录"为唯一数据源。 |

## 2. 计件公式（每日班组池，含开关）

对班组 T、日期 d：

```
MAWE_d , L_d , H_d   = 当日三类物料装载车次（已强制按物料分别记车）
total_d              = MAWE_d + L_d + H_d
单价                 = MAWE 3,000 / NICKEL L 5,000 / NICKEL H 8,000   (TZS / 车)
目标车次             = 40  （固定班组目标，不随人数缩放）
exempt_d             = 当日是否经确认为"可控缺量"（设备故障/矿面未备/等指令）
multiplier_d        = accelerator_enabled ?
                          ( exempt_d ? 1.0 : total_d / 40 )      # 开关 ON
                          : 1.0                                  # 开关 OFF → 线性
pool_{T,d}          = ( MAWE_d × 3000 + L_d × 5000 + H_d × 8000 ) × multiplier_d
```

**凸性示例（开关 ON）**：50 车 → ×1.25；30 车 → ×0.75；80 车 → ×2.0（超产大奖，固定时长下极难达成，倍数不封顶）。
**开关 OFF 示例**：无论 30 / 50 / 80 车，`multiplier = 1.0`，日池 = 纯线性「物料 × 单价」。

---

## 3. 每日分配（均分到人）

```
headcount_{T,d} = 当日实际出勤人数（二元判定，见 §5）
per_head_{T,d}  = pool_{T,d} / headcount_{T,d}
```

每名**出勤**工人 W，将其当日所在班组的 `per_head` 累加入个人基数：

```
base_W = Σ_{d : W 当日出勤于班组 T(W,d)} per_head_{T(W,d), d}
```

**性质**：每个班组池在当日被完全均分，`Σ_W base_W = Σ_{d,T} pool_{T,d} = 全月固定总额 F`。
（开关 OFF 时 `base_W` 即为该工人最终应得的线性计件累加值，月末不再重分配。）

---

## 4. 跨班组临时互调处理

以 **"当日实际所在班组"** 为产量与分配归属的唯一基准：

1. 互调工人当天在哪个班组出工，就计入该班组当日池，并按 §3 均分取份额。
2. 其原属班组当日池**不含**此人。
3. 落地依赖一份**每日实际花名册**（字段：日期 / 工人 ID / 实际所在班组 / 出勤判定），驱动全部归属。
4. 互调工人若当日无宿主班互评数据，使用其**滚动行为分**（见 §8），避免宿主班偏见。

> 此机制与开关状态无关：无论线性或凸性，互调归属逻辑一致。

---

## 5. 出勤判定（二元制）

| 判定 | 取值 | 说明 |
|---|---|---|
| 出勤 | 1.0 | 当日实际完成当班作业（中方判定） |
| 缺勤 | 0 | 未到岗；**"露脸就走"（到场但未完成作业）同样判为缺勤** |

缺勤当日：`headcount` 不计此人，其 `base` 不含该日份额（即当日 0 收入）。

---

## 6. 可控缺量豁免

- 因**设备故障 / 矿面未备 / 等待指令**等不可控原因导致欠量，经中方确认 → 当日 `exempt_d = true` → 倍率**强制按 1.0 计**（不惩罚）。
- 仅"在井但磨洋工"才触发 `< 1.0` 的倍率。
- 此豁免仅在**开关 ON** 时有实际效果（开关 OFF 时倍率本就恒为 1.0）。

---

## 7. 月末系数（出勤 + 行为）与总额固定约束（仅开关 ON 生效）

对每名工人 W：

```
A_W = min( 出勤天数_W / (26 − exempt_days_W) , 1.0 )   # 满 26 天 = 1.0 全勤；合法缺勤分母同步降，不罚
B_W = 行为系数（见 §8，建议范围 0.7 – 1.3）
C_W = w_a × A_W + w_b × B_W                  # 权重 w_a > w_b，建议 w_a=0.6, w_b=0.4
raw_W = base_W × C_W
k     = F / Σ_W raw_W                        # F = Σ base_W = 固定总额
final_W = raw_W × k
```

**总额恒定证明**：`Σ final_W = k × Σ raw_W = k × (F / k) = F` ✓

归一化因子 `k` 是同一个标量乘给所有人，因此**不改变高低排序**（C_W 越高者 final 占比越高，差距被拉大），但总额被压回固定值 F——即你要的"系数人人不同，但总资金固定、不多发不少发"。

> **开关 OFF 时**：直接 `final_W = base_W`，不做任何月末再分配，与现有线性计件完全一致。

## 8. 权重、评分来源与行为分

- **互评 ≠ 行为分**（两者不同，但互评是行为分的主数据源）：
  - 互评 = 原始输入机制：同伴匿名对 5–6 维打分（主动 / 勤快 / 纪律 / 协作 / 安全 / 驾驶）。
  - 行为分 = 派生输出：去极值 → 工友分 + 管理分（管理票权重 1.5）→ 映射为系数（建议 0.7–1.3）。行为分还吸收安全记录等非互评输入。
- **滚动行为分**：每名工人维护近 4 周互评 + 管理评分的均值，每周更新；互调日无宿主班互评时直接使用滚动值。
- **权重取向**：`w_a > w_b`（出勤占比更高），目的——出勤可靠性是抑制"挑活干 / 井下困难就消失"的主要杠杆。
- **出勤双重计算（已确认采用方案 a）**：二元出勤已在 `base` 中排除缺勤日，月末 `A_W` 又对缺勤 <1，**缺勤被罚两次**。本规格采用「保留」方案，将 `A_W` 视为"月度可靠性"的额外惩罚，治懒更狠，贴合"出勤占比要更高"的意图。合法缺勤（L/NU/E，见 §5 判定外的豁免标记）通过 `exempt_days` 在分母中扣减，不重复罚。

## 9. 结算与公示周期

| 周期 | 动作 |
|---|---|
| 每日 | 核算各班组池、按人头均分（§3），写入当日实际花名册 |
| 每周 | 公示看板（字段见下）；动机闭环短，强化治懒 |
| 月末 | 开关 ON：按 §7 计算 `final_W` 并实发；开关 OFF：按 `base_W` 实发 |

**周公示看板字段**：班组 / 当日车次(MAWE·L·H) / 基础池 / 倍率 / 班组池 / 各人 base / 各人 C（仅 ON）/ 各人 final 预估（仅 ON）。

## 11. 计算示例（验证开关两态 + 总额固定）

### 示例 A：开关 OFF（线性普通计件）
两名工人，全月出勤日均分累加 `base_X=600,000`、`base_Y=400,000`，`multiplier≡1.0`。
月末直接 `final = base`，**不做再分配**：
`final_X = 600,000`，`final_Y = 400,000`，Σ = 1,000,000（与日池之和恒等，线性形态）。

### 示例 B：开关 ON（凸性 + 月末再分配）
同一 base，加月末系数（X 满勤高行为，Y 缺勤低行为）：

| 工人 | base | 出勤天 | A_W | B_W | C_W=0.6A+0.4B | raw=base×C |
|---|---|---|---|---|---|---|
| X | 600,000 | 26 | 1.0 | 1.2 | 1.080 | 648,000 |
| Y | 400,000 | 20 | 0.769 | 0.8 | 0.7815 | 312,600 |
| | | | | | **Σraw=960,600** | |

```
k = 1,000,000 / 960,600 = 1.04102
final_X = 648,000 × 1.04102 = 674,581
final_Y = 312,600 × 1.04102 = 325,319
Σfinal ≈ 1,000,000  ✓ 总额固定
```

**结果解读**：开关 ON 时，X（满勤+高行为）由 600k 升至 674.6k，Y（缺勤+低行为）由 400k 降至 325.3k，差距由 200k 拉大到 349k 且总额恒定；开关 OFF 时差距保持 200k 线性。两者共享同一套日池数据，仅由开关决定"是否叠加凸性 + 月末再分配"。

## 12. 设计注意（已全部确认）

1. **凸性开关定位**：V2 是 piecework 模式的增量，由 `piecework_accelerator` 布尔开关控制。OFF=普通线性计件（安全回退），ON=凸性全量。已确认采用此开关化设计。
2. **出勤双重计算（已确认方案 a）**：二元出勤已排除缺勤日，月末 `A_W` 又对缺勤 <1，缺勤被罚两次，作为"月度可靠性"额外惩罚；合法缺勤经 `exempt_days` 在分母扣减，不重复罚。
3. **倍数不封顶**：80 车 = 4× 目标工资为超产大奖；固定时长下极难达成，成本风险由管理方承担。
4. **40 车目标**：由现场经验确认可行，不做历史回溯标定；目标为固定值、可编辑。
5. **物料记车前提**：§2 公式依赖 MAWE / L / H 三类车次分别记录，须由出库 / 地磅单现场落地，否则公式无法执行。
